# 관리 (관리자 전용)

왼쪽 메뉴 아래 **관리**는 관리자에게만 보입니다. 관리 PIN을 정했으면 처음 열 때 PIN을 입력합니다(프로그램을 다시 켜기 전까지 유지).

## 승인 관리
팀원의 사용 신청 목록입니다. 새 신청이 오면 탭에 빨간 숫자가 표시됩니다.

새 신청은 관리자 PC에 이렇게 알려 줍니다(창을 닫아 트레이에만 있어도 동작).

- 화면 오른쪽 아래 **Windows 알림**: 신청자 이름·부서, PC 이름, IP가 표시되고, 누르면 **승인 관리**가 열립니다.
- 왼쪽 메뉴 **관리**에 대기 건수가 빨간 숫자로 표시됩니다.
- 트레이 아이콘에 빨간 점이 표시되고, 처리할 때까지 유지됩니다.
- 프로그램이 꺼져 있거나 연결이 끊긴 동안 들어온 신청은 다시 연결될 때 "사용 신청 N건이 승인을 기다립니다" 알림으로 알려 줍니다.

방해 금지 시간에는 Windows 알림을 띄우지 않고 숫자와 트레이 표시만 남깁니다. 자동 승인된 신청은 알리지 않습니다.

- 신청마다 **이름·부서·직위, IP, PC 이름, Windows 계정, 신청 시각**이 보입니다.
- **허용 대역 밖** 표시가 있으면 사내망 밖에서 온 신청일 수 있으니 확인 후 처리하세요.
- **승인**: 바로 사용할 수 있게 됩니다. / **거절**: 신청자 화면에 거절이 표시됩니다.
- **고유값**: 신청한 PC의 고유값입니다. **이미 등록된 PC입니다**라고 나오면 전에 승인했던 PC가 다시 신청한 것입니다. 승인하면 **새 계정을 만들지 않고 이전 계정으로 연결**하고, 그 PC의 이전 연결은 끊습니다. 고유값이 없던 이전 버전에서 같은 PC가 여러 사람으로 등록되어 있었다면, 다시 승인할 때 가장 최근 계정 하나만 남기고 나머지 중복 계정은 **사용 중지**로 바꿉니다(자료는 지워지지 않습니다).
- 같은 PC가 답을 받기 전에 다시 신청하면 이전 신청은 사라지고 새 신청 하나만 남습니다.
- **영구 차단**: 모르는 PC가 계속 신청할 때 씁니다(아래 **PC 차단** 참고).

## 구성원·PC
**구성원** 표
- **관리자 지정 / 관리자 해제**: 관리자는 최소 1명이어야 합니다.
- **사용 중지 / 다시 사용**: 중지하면 그 사람의 모든 PC가 즉시 차단됩니다.
- **정보 수정**: 팀원이 입력한 이름·부서·직위·내선번호·휴대폰·담당 업무를 고칩니다. 여기서 고친 항목은 **서버 PC의 값이 우선**합니다. 저장하면 모든 팀원 화면에 바로 반영되고, 그 팀원은 고친 항목을 스스로 바꿀 수 없게 됩니다(내 정보에 "관리자가 정한 항목"으로 표시). 고치지 않은 항목은 팀원이 계속 바꿀 수 있습니다. **별명**은 본인만 정할 수 있어 여기에 없습니다. 기관·팀 이름은 **조직·운영 설정**에서 바꿉니다.

**승인된 PC** 표
- 녹색 점은 지금 접속 중인 PC입니다.
- **IP 변경** 표시: 승인 당시와 다른 IP로 접속하고 있습니다. 정상이면 **새 IP 인정**을 누릅니다.
- **고유값**: 그 PC의 고유값입니다(이전 버전에서 승인한 PC는 업데이트 후 접속하면 채워집니다).

### PC 차단
| 단추 | 하는 일 | 다시 쓰려면 |
|---|---|---|
| **차단** | 그 PC의 접속을 바로 끊습니다(분실·교체·잠깐 막을 때). | **차단 해제**를 누르면 이전 승인 그대로 다시 접속합니다. 또는 그 PC에서 **다시 사용 신청**을 하고 승인하면 같은 계정으로 연결됩니다. |
| **영구 차단** | 접속을 끊고, 그 PC에서는 **사용 신청도 할 수 없게** 합니다. 프로그램을 다시 설치해도 풀리지 않습니다. | 아래 **영구 차단한 PC** 목록에서 **차단 해제** → 그 PC에서 다시 사용 신청 → 승인. |

- 영구 차단은 신중하게 하도록 **차단 사유**를 반드시 적고 확인란에 체크해야 진행됩니다. 사유와 차단한 사람·날짜는 목록과 기록에 남습니다.
- 지금 쓰고 있는 PC, 서버 PC, 관리자의 PC는 영구 차단할 수 없습니다(관리자 PC는 먼저 관리자 해제).
- 영구 차단해도 구성원 계정과 그 사람이 올린 자료는 지워지지 않습니다.
- 영구 차단한 PC는 PC 이름과 Windows 계정으로도 알아보므로, 새로 설치해 고유값이 바뀌어도 신청할 수 없습니다.

## 조직·운영 설정
변경 후 아래의 **설정 저장**을 누릅니다. 저장하면 접속 중인 모든 팀원 화면에 바로 반영됩니다.

| 항목 | 설명 |
|---|---|
| 조직 정보 | 기관/회사명, 소속 팀명, 하단 안내문 |
| 네트워크·승인 | 포트(바꾸면 서버가 다시 시작되며 팀원은 새 주소로 다시 연결), 허용 IP 대역(쉼표 구분), 허용 대역 안 자동 승인, IP 변경 시 재승인 |
| 저장 공간 | 전체 용량 한도(GB, 기본 200), 파일당 최대 크기(GB, 기본 5, 소수 가능), 올릴 수 없는 확장자. 지금 사용량과 디스크 여유 공간이 함께 표시됩니다. 한도가 남아도 서버 PC 디스크의 여유 공간이 모자라면 올릴 수 없습니다. |
| 백업 | 백업 위치, 매일 백업 시각, 보관 개수 |
| 운영 | 긴급알림 발송 권한, 그룹 만들기 권한, 메시지 보관 기간, 절전 방지 |
| 사용할 기능 | 끈 기능은 모든 팀원의 메뉴에서 숨겨집니다. |
| 관리 PIN | 새 PIN 입력 후 **PIN 저장**. 비우고 저장하면 PIN이 해제됩니다. |

## 백업·복구
- **지금 백업**: DB와 첨부·자료실 파일을 백업 위치에 저장합니다. 매일 정한 시각(조직·운영 설정의 백업)에도 자동으로 하고, 정한 개수만큼 보관합니다. 파일은 바뀐 것만 새로 복사합니다.
- **이 백업으로 복구**: 서버가 잠시 다시 시작하며 그 시점으로 되돌립니다. 지금 상태는 `backups/before-restore-시각.db`로 따로 남습니다.
- 백업 위치는 서버 PC가 아닌 다른 드라이브·NAS·USB를 권장합니다.

## 서버 자료 저장 위치
서버 PC에서만 보입니다(관리 → 백업). 공지·일정·자료실 파일·대화·기록·백업(기본 위치)·배포 파일 등 서버 자료 전체를 다른 폴더로 옮깁니다. 서버 PC의 드라이브가 꽉 찼거나 더 큰 드라이브로 옮길 때 사용합니다.

1. **폴더 바꾸기…** 를 누르고 **빈 폴더**를 고릅니다. 드라이브 맨 위를 고르면 그 안에 `TeamHub 서버 자료` 폴더를 만듭니다.
2. 확인 창에서 옮길 자료의 크기와 빈 공간을 확인하고 **옮기기**를 누릅니다.
3. 서버가 잠시 멈추고 → 복사 → 검사 → 새 폴더에서 서버 시작 → 이전 폴더 정리 순서로 진행되며 진행 상황이 표시됩니다.

- 옮기는 동안(자료 양에 따라 몇 초~몇 분) 팀원은 접속할 수 없고, 끝나면 자동으로 다시 연결됩니다. 업무 시간이 아닐 때 하세요.
- 복사·검사에 실패하거나 새 폴더에서 서버가 켜지지 않으면 이전 폴더로 서버를 다시 켜고, 새 폴더에 만든 파일은 지웁니다.
- 백업 위치를 따로 정해 두었다면 그 위치는 바뀌지 않습니다(서버 자료 폴더 안에 정해 둔 경우에만 함께 옮겨집니다).
- 이미 TeamHub 서버 자료가 있는 폴더로는 옮길 수 없습니다. 백업을 되살리려면 **이 백업으로 복구**를 쓰세요.
- 네트워크 폴더에는 둘 수 없습니다(데이터베이스가 손상될 수 있음).

## 서버 PC 바꾸기 (서버 이전)
1. 예전 서버에서 **지금 백업**을 누릅니다.
2. 백업 위치의 **TeamHub-날짜** 폴더와 **blobs** 폴더를 함께 새 PC로 복사합니다(같은 폴더 안에).
3. 새 PC에 TeamHub를 설치하고 첫 화면 아래 **기존 서버의 백업으로 이 PC를 서버로 만들기**를 누릅니다.
4. 백업 폴더(TeamHub-날짜)를 고르고, 이 PC를 쓸 관리자와 데이터 폴더를 정한 뒤 **옮겨 오기**를 누릅니다.
5. 예전 서버 PC는 끄거나 접속 모드로 바꿉니다. 팀원은 다시 승인받을 필요가 없고, 새 서버를 자동으로 찾지 못하면 표시된 새 주소를 **설정 → 서버 연결**의 서버 주소를 고치고 **적용**(또는 **서버 다시 찾기**)에 넣습니다.

## 공휴일
- 연도를 고르면 등록된 공휴일 목록이 나옵니다. 기본 공휴일이 들어 있습니다.
- 날짜와 이름을 입력하고 **추가·수정**을 누르면 기관 휴일을 추가하거나 이름을 고칩니다.
- 휴지통 버튼으로 잘못된 날을 지웁니다.
- 모든 팀원의 일정 달력에 붉게 표시됩니다.

## 공용 런처·보안
- **공용 런처 항목**: 업무 사이트, 공용 폴더·문서, 양식 파일을 등록하면 모든 팀원 런처의 **팀 공용·양식함**에 나타납니다. 실행 파일은 등록할 수 없습니다.
- **보안 점검 지정 프로그램**: 팀원 보안 점검에서 실행 여부를 확인할 프로그램(프로세스·서비스 이름)을 등록합니다. 점검 결과는 팀원 PC에만 남고 관리자에게 보이지 않습니다.
- 자세한 사용법은 도움말 "런처", "유틸리티" 장을 봅니다.

## 업데이트 배포
- **다운로드 사이트에서 가져오기**: 팀원 PC가 폐쇄망일 때, 서버 PC(인터넷 필요)가 다운로드 사이트의 최신 버전을 받아 사내에 배포합니다. 받은 파일의 해시를 확인한 뒤 등록합니다.
- 서버 PC도 인터넷이 없으면 다운로드 사이트에서 받은 설치 파일을 아래 순서로 직접 올립니다.
1. **설치 파일**에서 새 `TeamHub-Setup-x.y.z.exe`를 고릅니다. 파일 이름의 버전이 **버전** 칸에 자동으로 들어갑니다. 설치 파일의 실제 버전과 **버전** 칸이 다르면 등록되지 않습니다.
2. 필요하면 **필수 업데이트**를 체크하고 **변경 내용**을 적습니다. 필수 업데이트는 자동 업데이트를 꺼 둔 PC도 내려받습니다.
3. **배포**를 누릅니다. 접속 중인 PC가 자동으로 내려받고, 꺼져 있던 PC는 다음 접속 때 받습니다. 서버 PC 자신도 같은 방식으로 업데이트됩니다.

- **팀원 설치 버전**: 버전별 PC 대수입니다. 녹색이 현재 배포 버전입니다.
- 서버에는 **최신 버전 하나만** 보관합니다. 새 버전을 등록하면 이전 버전의 설치 파일과 기록은 지워집니다. 지금 버전보다 낮은 버전은 올릴 수 없습니다.
- **배포 회수**: 그 버전 배포를 멈춥니다(팀원 PC가 더 이상 받지 않음). 이미 설치한 PC는 그대로입니다. 다시 누르면 배포를 재개합니다.

## 서버 상태
접속 중인 인원, 연결 수, 승인 대기, 디스크 사용량, 서버 버전, 실행 시작 시각, 데이터 폴더, 최근 오류를 보여 줍니다. 디스크 사용량이 90%를 넘으면 경고가 표시됩니다.

## 활동 기록
사용 신청·승인, PC 중지, 설정 변경, 배포 등 변경 작업이 시각·사용자·IP와 함께 기록됩니다.
